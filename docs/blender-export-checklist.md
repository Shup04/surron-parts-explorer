# Blender → Sur-Ron model import checklist

Work on a saved copy of the `.blend`. The studio inspects imports without repairing names, geometry, origins or transforms.

1. **Organize the motorcycle.** Use collections for authoring organization and parent Empty objects for exported assemblies: `motorcycle → jackshaft-assembly → shaft / bearing-left / bearing-right`. Check that the exported parent hierarchy appears in Scene objects; collection membership alone is not a component parent relationship.
2. **Keep components separate.** Each independently selectable part needs its own mesh object. Do not join a bearing, shaft and washers into one object. Linked mesh data is fine when occurrences remain separate objects. Avoid GPU instancing for parts needing separate mappings; this studio selects the instanced object as a group.
3. **Name and identify objects.** Use descriptive, unique names such as `jackshaft-bearing-left`. Optionally use `part__<catalog-id>` for existing matching suggestions. Add a unique **string** custom property named `objectId` to each component and assembly Empty. Save it in the `.blend`; give duplicates new IDs and keep IDs for unchanged physical occurrences. Names and IDs are different from OEM numbers.
4. **Verify scale deliberately.** Use Metric units and check a known source dimension. In the app, **1 m = 1,000 mm**; a measured 100 mm feature must export as 0.1 m. Changing Blender's unit display alone does not correct geometry. The preflight gives an axis-aligned scene bounding box in metres, not a physical-size certification. glTF uses metres and Y-up. [Khronos coordinate conventions](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#coordinate-system-and-units).
5. **Apply transforms carefully.** Prefer predictable scale before mapping. On the working copy, inspect object and parent scales, including mirrored or nonuniform scales. Apply Scale only when you understand its effect on modifiers, constraints, linked data and parenting; then recheck assembled positions and dimensions. Do not apply Location or Rotation indiscriminately: origins and local axes may change. Blender documents these dependencies under [Apply transforms](https://docs.blender.org/manual/en/latest/scene_layout/object/editing/apply.html).
6. **Choose useful origins and axes.** Put shaft/bearing origins on their intended axes and assembly Empty origins at useful references, while preserving assembled geometry. Do not move every origin to world zero. This viewer's explosion offsets translate along each object's **parent axes**; parent scale affects world travel. Distant-origin warnings are review prompts, not proof of an error. The report cannot infer correct mechanical pivots or disassembly directions.
7. **Export GLB.** Choose glTF 2.0, **glTF Binary (.glb)**, **+Y Up** and **Custom Properties**. Export the intended objects with their assembly parents; exclude construction meshes, cameras and lights. Disable animations for static mechanical assets. Decide modifier export deliberately and inspect the resulting mesh. Use the same options on subsequent exports. The Blender manual describes [GLB packaging, coordinate conversion and custom properties](https://docs.blender.org/manual/en/4.1/addons/import_export/scene_gltf2.html); option placement varies by version.
8. **Check the import before mapping.** Open **Import preflight** below the studio preview. Review counts, original names, hierarchy, metre bounds, transforms and mapping-key warnings. Expand the object tree and select components individually. Verify a known measurement in Blender or your CAD source; plausible bounds alone are insufficient. Map a small assembly, preview explosion/reassembly, then save locally and export mapping/project JSON.
9. **Preserve mappings on re-export.** Keep `objectId` values, catalog IDs, parent axes and assembled transforms stable. Fallback keys depend on names, sibling order and hierarchy; review mappings if any of those change. Changing transforms can require new explosion directions/distances even with stable IDs. Export a versioned GLB, import it into the existing workspace, inspect retained/missing mappings, and test reassembly before replacing a published asset. Keep the previous GLB and mapping JSON as a pair.

The report covers the loaded default scene. Loaded counts can include extra render meshes for material primitives, and triangle totals count repeated instances. It flags local/inherited scale factors below 0.01 or above 100 and static mesh origins more than two local bounding-box diagonals outside their geometry. These are deliberately broad review thresholds. Skinned/morphing and instanced-mesh pivots require manual inspection. No warning establishes Sur-Ron dimensions or fitment.

See the [full model pipeline](model-pipeline.md) for CLI validation and the optional conservative Blender export helper. Blender export itself still requires testing with your installed version and actual models.

## Shading after mesh reduction

Keeping smooth vertex normals does not preserve every highlight after aggressive decimation. For the supplied frame and swingarm, bake the original high-resolution surface normals onto the reduced mesh's unique `FinishUV` layout. Finalize smoothing/sharp-edge modifiers before baking so the tangent basis stays consistent. Feed the bake to both the Principled shader's **Normal** and **Coat Normal** inputs; the clearcoat otherwise continues to show coarse geometry shading. The supplied correction keeps the existing metallic/roughness flake texture and replaces the flake-only bump.

With the original local source files available, regenerate into a new staging directory:

```sh
blender --background reference/models/surron-parts/frame-update/surron-parts-ready.blend \
  --python scripts/bake-part-normals.py -- --output /tmp/surron-normal-bakes
```

The script does not save either source `.blend`. It checks the exported triangle positions, UVs, transforms, paint color and metallic/roughness texture against the published models, then writes the GLBs, normal PNGs and provenance report. Inspect close-up renders under the same camera and lighting before replacing the two public GLBs, updating their manifest hashes/sizes and copying the report to `data/models/surface-normals.json`. Texture memory and download size increase; triangle counts and silhouettes remain unchanged.
